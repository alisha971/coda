# Conversational Delivery Adaptation (CODA)

**Conversational Delivery Adaptation: a controlled measurement of how a partner's delivery predicts a reply's delivery.**

In spontaneous dyadic conversation, and conditional on the reply's own words and the partner's transcript, is the reply's prosodic delivery predictively related to the partner's delivery, for speakers never seen in training? Does the strength or structure of that relationship depend on the conversational function of the turn pair?

**Start here: [`docs/research_overview.md`](docs/research_overview.md).** It explains the question, the design, and why each component exists, without assuming familiarity with the project.

**Technical report: [view the report](https://coda-report-lr5a.vercel.app/).** It describes the data, the method and the results obtained so far, with figures and listening examples.

## What this is, and is not

CODA is a measurement study. It estimates how much the partner's delivery contributes to predicting a reply's delivery, beyond the text both speakers produce, evaluated on speakers held out entirely.

It generates no audio. There is no text-to-speech, no voice or style transfer, and no end-to-end agent. The quantity estimated is a conditional predictive dependence.

## Reproducing

```bash
python -m pip install -e .
python -m pytest tests/ -q
python -m ruff check src tests
```

The notebooks run on Google Colab from a copy of this repository on Google Drive (`MyDrive/coda/`). Every path goes through `src/paths.py`, so the layout on Drive and in the repository is identical. Audio stages use a CPU runtime. Only the self-supervised feature extraction and the neural layer need a GPU. The statistical core runs without a GPU. Pinned packages are in `environment.yml`, `requirements.txt` and `requirements-colab.txt`.

The sample is fully determined by public data: the dataset revision and file-index commit in `configs/corpus.yaml`, the selection seed, and `manifests/coda_download_manifest.csv`, which notebook `01` regenerates and checks byte for byte.

Method settings (overlap handling, pitch range, penalty grid, bootstrap, donor matching, calibration and gate rules) are fields of `Settings` in `src/settings.py`. Every run record stores the values in force, and every output name carries a signature of the measurement settings, so results from different definitions never overwrite each other.

## Data

The Seamless Interaction dataset, naturalistic partition (Agrawal et al., 2025), CC BY-NC 4.0, openly downloadable: stranger dyads in prompted, unscripted conversation, one microphone per participant, word-timed transcripts. Only audio, transcripts and voice-activity segments are fetched. Video is never requested. Audio is processed and discarded: it is measured, then deleted. No audio or corpus-derived cache is included in this repository.

## Status

The pipeline has been run on the 250-session sample through calibration (notebooks `00` to `12` and `14`). Channel quality control, the delivery targets, the speaker-disjoint split, the content-only baseline, donor construction and the positive control are complete. At zero injected effect, both donor tests reject a true null above their nominal size, so the calibration gate is not passed and the confirmatory tests (notebooks `16` to `19`) have not been run. The neural layer (notebooks `13`, `15` and `18`) is deferred. The technical report linked above describes these results.
